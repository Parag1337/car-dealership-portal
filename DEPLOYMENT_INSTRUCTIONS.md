# Deployment Instructions — Render Blueprint

> Status: configuration verified locally; **no production deployment has been
> performed from this working tree.** Do not treat the app as deployed until
> the steps below succeed against the real public URL.

This project deploys as a single Render web service (Django serves both the
API and the React production build from the same origin) plus a Render
PostgreSQL database, as defined in the root-level `render.yaml` Blueprint.

## 1. Create the Blueprint service (manual — Render dashboard)

1. Push this repository to GitHub (public repo URL goes in `README.md`).
2. In the [Render dashboard](https://dashboard.render.com), click **New → Blueprint** and select this repository.
3. Render detects `render.yaml` and proposes two resources:
   - Web service `car-dealership-portal` (`env: python`, region `oregon`, `plan: free`)
   - Database `car-dealership-db` (PostgreSQL, `plan: free`)
4. Click **Apply**. Render then runs, from the repo root:
   - Build: `chmod +x server/build.sh && ./server/build.sh`
     (`pip install -r requirements.txt` → React `npm install && npm run build`
     → `collectstatic` → `migrate` → idempotent `populate_data`)
   - Start: `cd server && gunicorn djangoproj.wsgi:application --bind 0.0.0.0:$PORT --workers 4 --timeout 120`
   - Health check: `GET /` (serves the React app once the frontend build exists)

## 2. Environment variables

`render.yaml` sets these automatically — verify them in **Dashboard → Service → Environment**:

| Key | Value / source | Notes |
|---|---|---|
| `PYTHON_VERSION` | `3.11.0` | Must match `server/runtime.txt` (`python-3.11.0`) |
| `DEBUG` | `"False"` | Enables HTTPS redirect, secure cookies; code refuses to boot in prod without `SECRET_KEY`/`ALLOWED_HOSTS` |
| `SECRET_KEY` | `generateValue: true` | Generated by Render. Never commit a real secret; dev fallback works only with `DEBUG=True` |
| `ALLOWED_HOSTS` | `.onrender.com,car-dealership-portal.onrender.com,localhost,127.0.0.1` | Update the middle hostname if your service name differs |
| `DATABASE_URL` | from `car-dealership-db` | Linked automatically; selects PostgreSQL in `settings.py` |
| `DJANGO_SETTINGS_MODULE` | `djangoproj.settings` | Matches `startCommand` (`cd server` first) |
| `CORS_ALLOWED_ORIGINS` | `https://car-dealership-portal.onrender.com` | Consumed by `settings.py`; same-origin app needs no CORS, this covers a decoupled frontend |
| `SECURE_SSL_REDIRECT` / `SECURE_PROXY_SSL_HEADER` | `"True"` / `"HTTP_X_FORWARDED_PROTO,https"` | Informational: `settings.py` derives both from `DEBUG=False` for Render's proxy |

If you rename the service, update `ALLOWED_HOSTS` and `CORS_ALLOWED_ORIGINS` to the actual generated hostname (e.g. `https://<name>.onrender.com`).

## 3. Database setup and sample data

- Migrations run automatically during every build (`python manage.py migrate`), before seeding.
- `populate_data` is **idempotent**: makes/models/dealers are `get_or_create`d, users are only created when missing (existing passwords and reviews are preserved), and seed reviews are keyed on `(dealer, customer, review_text)` so re-runs never duplicate or crash. Seed failures now fail the build loudly instead of being hidden.
- To seed or top up an existing database manually (Render Shell tab):
  ```bash
  cd server
  python manage.py migrate
  python manage.py populate_data
  ```

## 4. Create an admin user (manual — Render Shell)

```bash
cd server
python manage.py createsuperuser
```

Then open `https://<your-app>.onrender.com/admin/`.

## 5. Verify the deployment

Replace `<your-app>` with the real hostname and check each:

1. **Homepage:** `https://<your-app>.onrender.com/` renders the React dealer listings (not the API-status JSON — that JSON means the frontend build step was skipped; see troubleshooting).
2. **API:** `https://<your-app>.onrender.com/api/dealers/` returns HTTP 200 JSON.
3. **Auth:** register at `/register`, confirm the username appears, then log out and log back in at `/login`.
4. **Reviews:** open a dealer, post a review while logged in, confirm it appears with a sentiment badge; confirm logged-out posting is rejected.
5. **Admin:** log in at `/admin/`, then log out and confirm the "Logged out" page.
6. **Static pages:** `/static/About.html` and `/static/Contact.html` render styled.

Only after these pass, write the live URL into the `deploymentURL` file and capture the `deployed_*.png` screenshots.

## 6. Troubleshooting

- **Build fails at `populate_data`:** read the error — it is real (no longer swallowed). Common cause: `migrate` did not run against the linked database; check `DATABASE_URL`.
- **Homepage shows API-status JSON:** the React build is missing — check build logs for the "Building React frontend" step (`npm` must be available in the build environment).
- **`collectstatic` errors:** `STATICFILES_STORAGE` is manifest-based; a missing referenced asset fails the build. Check the log for the offending file.
- **DisallowedHost / 400:** `ALLOWED_HOSTS` does not include the service hostname; update it (no `*` allowed in production).
- **Redirect loops or health-check failures:** `SECURE_SSL_REDIRECT` relies on Render's `X-Forwarded-Proto` header; verify proxy headers in the dashboard.
- **Out of memory:** the free plan has limited RAM and `gunicorn` starts 4 workers; if the service OOMs, reduce `--workers` in `render.yaml` `startCommand`.
- **Free-tier database limits:** verify current Render free PostgreSQL retention/sleep policy in the dashboard before relying on it for grading data.
